### 2. GitHub AI Scan支持通过REST API批量管理仓库扫描

- **状态：** new
- **类别：** AI代码安全 / 企业治理
- **来源与热度信号：** GitHub 11月13日官方Changelog；使用量、扫描检出率和误报率未核实。
- **发布时间：** 2026年11月13日（官方页面日期），北京时间具体时刻未核实。
- **一句话摘要：** GitHub在公开预览中为组织和仓库AI Scan启用接口增加 `repository_scan` 设置，可用REST API或基础设施即代码批量控制仓库扫描。
- **为什么现在值得看：** 大型组织可以统一管理AI辅助安全扫描的启用范围，减少逐仓库手动配置，便于设置审批和成本边界。
- **与现有方案的关键差异：** 相比此前PR级别的 `pr_scan` 设置，这次扩展到仓库级扫描配置；启用并不会自动执行扫描，仍需有写入权限的用户按需触发。
- **使用门槛与适合谁：** 组织所有者、安全管理员及仓库管理员；公开组织仓库可用，私有/内部仓库需要GitHub Code Security或Advanced Security；企业策略可阻止启用，GitHub Enterprise Server暂不支持。组织禁用时仓库不能覆盖启用；冲突请求返回422。
- **价格或许可证：** 每次扫描消耗GitHub Code Security AI credits，具体单次成本未核实。
- **证据边界：** 官方确认接口和权限，不代表扫描效果已独立验证，也不代表打开设置后已扫描。
- **证据标签：** 一手来源确认
- **原始链接：** [GitHub官方Changelog](https://github.blog/changelog/2026-11-13-manage-ai-scan-for-repositories-using-the-rest-api/)
