### 1. Git发布六项安全漏洞修复：递归克隆恶意仓库可能执行代码

- **状态：** new
- **类别：** 开发者安全 / 软件供应链
- **来源与热度信号：** GitHub官方安全公告（11月10日）；社区排名、评论及实际受影响部署数量未核实。
- **发布时间：** 2026年11月10日，具体北京时间未核实。
- **一句话摘要：** Git 2.56.1修复六项漏洞，包括恶意仓库递归克隆时的代码执行、引用路径穿越、合并和二进制补丁处理中的内存问题，以及fast-import不安全文件访问。
- **为什么现在值得看：** 自动编码Agent、CI和仓库托管服务频繁处理第三方代码；风险不局限于人工运行Git的工作站。尤其应检查自动克隆不可信仓库的执行环境。
- **与现有方案的关键差异：** 这是Git底层漏洞修复，不是代码扫描器新增检测；仅加强仓库内容审查不能代替修补Git可执行程序。
- **使用门槛与适合谁：** 开发者、CI维护者及托管平台应升级到2.56.1，或维护分支对应的2.55.1、2.54.1、2.53.1、2.52.1、2.51.3、2.50.2；检查IDE、容器及自动化工具内嵌Git。GitHub Enterprise Server对应修复版本为3.19.15、3.20.11、3.21.9、3.22.4。暂不能升级时限制不可信递归克隆、合并、补丁和fast-import处理，但不能替代修复。
- **价格或许可证：** Git开源工具，升级费用未核实。
- **证据标签：** 一手来源确认
- **原始链接：** [GitHub原始安全公告](https://github.blog/open-source/git/git-security-vulnerabilities-announced-7/)

### 3. GitHub将暂停长期不活跃仓库的Dependabot漏洞提醒

- **状态：** new
- **类别：** 软件供应链 / 安全治理
- **来源与热度信号：** GitHub 11月10日官方Changelog；受影响仓库数量未核实。
- **发布时间：** 公告2026年11月10日；计划生效2026年12月8日。
- **一句话摘要：** GitHub计划对过去一年没有指定活动的大多数仓库关闭Dependabot alerts；现有提醒归档而非删除，恢复启用后可重新查看。
- **为什么现在值得看：** 不常修改但仍被部署或作为依赖使用的仓库可能失去持续漏洞提醒，需要提前识别。
- **与现有方案的关键差异：** 活跃度以推送分支或标签、创建仓库、开启Dependabot alerts等事件判断；仓库仍有生产用途并不自动算活跃。
- **使用门槛与适合谁：** 维护长期稳定项目、归档仓库和企业安全基线的团队应检查安全配置。强制启用提醒的安全配置、某些企业策略可避免暂停；推送或手动重新启用可恢复。GitHub Enterprise Server不适用。
- **价格或许可证：** 适用于github.com所有计划及具有数据驻留的Enterprise Cloud；未披露额外收费。
- **证据标签：** 一手来源确认
- **原始链接：** [GitHub官方Changelog](https://github.blog/changelog/2026-11-10-dependabot-alerts-will-pause-on-inactive-repositories/)
