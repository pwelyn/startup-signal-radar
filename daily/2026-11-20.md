### 1. Azure DevOps到GitHub Enterprise的在线迁移正式可用

- **状态：** new
- **类别：** 企业开发基础设施 / 平台迁移
- **来源与热度信号：** GitHub 11月19日Changelog；迁移客户数及成功率未核实。
- **发布时间：** 2026年11月19日（官方日期；北京时间具体时刻未核实）。
- **一句话摘要：** GitHub宣布从Azure DevOps Services迁移至具有数据驻留能力的GitHub Enterprise Cloud的Enterprise Live Migrations（ELM）正式可用，迁移期间持续同步变更。
- **为什么现在值得看：** 对计划统一代码托管和编码Agent工作流的企业，迁移停机窗口、历史保留和CI接续是实际成本；正式可用降低了采用预览功能的风险，但不证明迁移零故障。
- **与现有方案的关键差异：** 相比一次性导入，ELM持续同步Git历史、分支、标签和PR（含评论与用户历史），切换时才完成最后迁移；Azure DevOps分支策略映射为GitHub rulesets。Azure Boards工作项和Pipelines定义仍保留在Azure DevOps，可重新连接。
- **使用门槛与适合谁：** Azure DevOps Services和GitHub Enterprise Cloud数据驻留环境的企业管理员。应先对一个低风险仓库验证身份映射、权限、规则、流水线与回滚；不应把“持续同步”理解为无需切换窗口。
- **价格或许可证：** 迁移服务单独收费及目标Enterprise订阅成本未核实。
- **证据标签：** 一手来源确认
- **原始链接：** [GitHub官方公告](https://github.blog/changelog/2026-11-19-enterprise-live-migrations-from-azure-devops-generally-available/)

### 2. GitHub Actions的RHEL 9/10托管Runner镜像正式可用于生产工作流

- **状态：** new
- **类别：** CI/CD / 企业Linux
- **来源与热度信号：** GitHub 11月19日Changelog；采用量未核实。
- **发布时间：** 2026年11月19日（官方日期；北京时间具体时刻未核实）。
- **一句话摘要：** GitHub-hosted larger runners的Red Hat Enterprise Linux 9和10镜像结束公开预览，正式支持生产工作流。
- **为什么现在值得看：** 在与生产部署相同的操作系统上运行CI，可减少发行版、系统库和包管理差异带来的部署问题。
- **与现有方案的关键差异：** 相比通用Linux Runner，提供官方支持的RHEL基础镜像和自定义镜像入口；不代表所有生产环境依赖或内核配置均一致。
- **使用门槛与适合谁：** GitHub Team及Enterprise Cloud，创建Linux x64 larger runner并选择RHEL partner image；已使用预览镜像的工作流无需迁移。需验证Runner规格、镜像软件包及企业合规要求。
- **价格或许可证：** Larger runner的实际计费和RHEL相关条款未逐项核实。
- **证据标签：** 一手来源确认
- **原始链接：** [GitHub官方公告](https://github.blog/changelog/2026-11-19-red-hat-enterprise-linux-runner-images-now-generally-available/)

### 3. GitHub数据驻留企业版支持通过OIDC向S3传输审计日志

- **状态：** new
- **类别：** 企业安全 / 审计基础设施
- **来源与热度信号：** GitHub 11月19日Changelog；实际部署量未核实。
- **发布时间：** 2026年11月19日（官方日期；北京时间具体时刻未核实）。
- **一句话摘要：** GitHub Enterprise Cloud with data residency（GHE.com）现支持通过OpenID Connect向Amazon S3流式传输企业审计日志。
- **为什么现在值得看：** 安全团队可减少在GitHub侧保存长期AWS凭据的需求，并把代码平台操作记录接入已有日志留存与审计流程。
- **与现有方案的关键差异：** 此前github.com已有OIDC方式，本次扩展到GHE.com数据驻留环境；OIDC减少静态凭据管理，但不自动保证日志完整性、S3访问隔离和保留策略正确。
- **使用门槛与适合谁：** GHE.com企业管理员与AWS安全管理员；需配置AWS信任关系、最小权限IAM角色、S3存储桶策略和日志验证。跨地域数据流向应单独审查。
- **价格或许可证：** S3存储与请求费用依AWS账单；具体费用未核实。
- **证据标签：** 一手来源确认
- **原始链接：** [GitHub官方公告](https://github.blog/changelog/2026-11-19-s3-audit-log-streaming-with-openid-connect-expands-to-ghe-com/)
